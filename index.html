02 / The gate Deterministic · never-false-positive

The guarantee is enforced in code, not hoped for

Every output is provenance-gated. The gate is deterministic and never-false-positive: a number or identifier that is not in the source cannot pass as Verified. Cortessa never certifies — the engineer signs off.

Verified

Shown only when a claim is provably a near-verbatim span of a cited source.

Draft

Unprovable claims are shown as Draft — never passed off as fact.

Refused

When the fact is not present, the system refuses rather than guess.

04 / Effectivity S1000D · configuration-aware

The right revision for the right variant

Supersession is a claim about time — Rev E replaced Rev D. Effectivity is a claim about configuration — Rev D still applies to hulls 1–4, Rev E from hull 5, both current at once. Serving the wrong one to the wrong variant is a safety event, and a search engine cannot tell the difference.

  • Configuration-aware answers. For S1000D technical publications, an answer is bound to the product configuration it applies to — modules for a different variant are withheld and reported, not silently blended in.
  • Undecidable is flagged, never guessed. Where applicability cannot be decided from the data, the answer says so — the same refusal ethos as the provenance gate.
  • Benchmarked. 0 wrong-variant leaks across the committed effectivity benchmark — eight configuration-scoped questions over a disclosed, purpose-authored S1000D corpus.
